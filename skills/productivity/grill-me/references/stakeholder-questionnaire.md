# Stakeholder Questionnaire

Use this reference when a remaining decision or fact belongs to someone who is
not in the conversation, so further questions to the user cannot settle it.

The recipient holds knowledge the user lacks. The questionnaire asks for exactly
that gap, in a form the recipient can answer alone or walk through in a meeting.

## Ask About The Send, Not The Subject

The user cannot answer the open decision, but can always answer two things. Ask
them in one round:

1. **Who is it going to?** Role, expertise, and relationship to the user. This
   sets the tone and how much context the document must carry.
2. **What do you need back?** The specific decisions or facts the user must
   walk away with.

Draft once both are known. Every item named in the second answer must be covered
by at least one question.

## Structure

```markdown
# <Questionnaire title>

**Purpose:** <why this exists and the decision riding on it>

**From:** <user> **To:** <recipient> **Answers will be used for:** <where they go>

## Context

<One paragraph for a reader who was not in the conversation.>

## How To Answer

<Deadline and rough effort. Partial answers and "I don't know" are useful.>

## <Theme>

### <One question, one idea>

_Why this matters: <one line, only where the question could be misread>_

>

## Anything Else?

<Anything we did not ask that we should know?>
```

## Rules

- Order questions most important first; the recipient may only make one pass.
- Ask one idea per question. Split compound questions.
- Put an empty answer stub under every question.
- Group under theme headings once there are more than a handful.
- Define any term the recipient may not know.
- Leave out anything the user can already answer.

Return the questionnaire in the conversation. Write it to a file only when the
user asks, at the path they choose.
